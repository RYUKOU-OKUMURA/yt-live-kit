## 1. 目的

v1（MVP 0.1.0）は「URL → タイムライン → 切り抜き素材」を通した。v2 では次の 2 点を達成する。

1. **日常運用の摩擦を消す** — やり直しが安く、待ち時間が見え、URL をコピペしなくてよい
2. **成果物の幅を広げる** — 切り出した素材から、ハイライトまとめ動画と縦型ショート動画を作れる

v1 で作った `services/` 分離、Codex CLI 連携、進捗コールバックの構造をそのまま踏襲する。**新しい依存は追加しない**（yt-dlp / ffmpeg / Streamlit / Codex CLI のみで完結する）。

## 3. 実装方針

### 3.1 スコープの改訂点（V0 で要件に反映する）

v1 要件 §6.1 は「自動編集（ジャンプカット、テロップ、BGM、まとめ編集）」を一括でスコープ外にしている。v2 では **この一部だけを解禁する**。境界を曖昧にしないため、明示的に線を引く。

| 項目 | v2 での扱い | 理由 |
|------|-------------|------|
| 複数区間の連結（無音・無加工） | **解禁**（FR-13） | ffmpeg の決定論的処理。編集判断を含まない |
| 縦横比変換（ぼかし背景合成） | **解禁**（FR-14） | 同上。レイアウトは固定 |
| 既存字幕（VTT）の焼き込み | **解禁**（FR-14） | 既に取得済みのデータを描画するだけ。文言を生成しない |
| ジャンプカット（無音・フィラー除去） | **スコープ外のまま** | 判定基準が主観的で、品質保証が困難 |
| テロップ生成（新規テキストの作成・配置） | **スコープ外のまま** | デザイン判断を含む |
| BGM・効果音の付与 | **スコープ外のまま** | 権利処理が別問題として発生する |
| トランジション・エフェクト | **スコープ外のまま** | 上と同じ |

**要約:** v2 で解禁するのは「**すでに存在する素材を、固定ルールで並べ替え・変形する**」処理のみ。新しい表現を生成する処理は引き続きスコープ外とする。

### 3.2 レイヤ分離（v1 を維持）

```
UI (Streamlit) / CLI (typer)
        ↓
services (pipeline, jobs, ytdlp, channel, vtt, compressor,
          ai_prompt, clips, highlights, ffmpeg, shorts, storage)
        ↓
data/{video_id}/ ...
```

**v2 の追加ルール:**

- UI にビジネスロジックを書かない（v1 と同じ）
- **ワーカースレッドから `st.*` を一切呼ばない。** ジョブ状態はファイルに書き、UI 側がポーリングして描画する（詳細は V2）
- ffmpeg のフィルタグラフは `services/` 内で組み立て、UI からは渡さない

### 3.3 AI 連携（v1 を維持）

1. プロンプトテンプレートは `prompts/` に分離する
2. 主方式は Codex CLI サブプロセス呼び出し（`services/ai_prompt.py` のパターンを踏襲）
3. 失敗時は「プロンプトファイルを開いて Cursor で生成」できるフォールバックを残す
4. **保存前に必ずバリデーションを通す。** ハイライト区間も、チャプター・切り抜き候補と同様のバリデータを持つ

**v2 での重要な設計判断:** Codex CLI 呼び出しは 1 回あたり数十秒〜数分かかる。したがって、

- **AI 呼び出しの単位を細かく分割し、個別に再実行できるようにする**（V1）
- **AI 呼び出し中に UI がブロックされないようにする**（V2）

この 2 つを、成果物系の機能（V5 / V6）より先に片付ける。

## 7. 追加する機能要件（V0 で requirements.md に転記する）

### FR-09: 機能の個別実行

| 項目 | 内容 |
|------|------|
| **入力** | video_id、実行対象（chapters / clips / highlights） |
| **処理** | 保存済みの整形テキストを入力に、指定ステップのみ実行する。字幕取得・整形は成果物があればスキップする |
| **出力** | 対象ステップの成果物のみ更新。既存成果物は上書き前に退避する |
| **スコープ** | UI とパイプラインの両方から呼べること |

### FR-10: 非同期実行と進行状況表示

| 項目 | 内容 |
|------|------|
| **入力** | 実行要求（単本 / 一括 / ハイライト / ショート） |
| **処理** | バックグラウンドスレッドで実行し、状態をファイルに永続化する |
| **出力** | 画面上部の常駐ステータスバーに、現在ステージ・メッセージ・経過時間・進捗を表示 |
| **スコープ** | 同時実行ジョブは 1 件まで。キューイングは対象外 |

### FR-11: テキストのコピー支援

| 項目 | 内容 |
|------|------|
| **入力** | 文字起こし全文、タイムライン、概要欄テンプレート |
| **処理** | クリップボードへのワンクリックコピー。テンプレートがあればタイムラインと結合する |
| **出力** | コピー完了のフィードバック表示 |

### FR-12: チャンネルからの URL 取得

| 項目 | 内容 |
|------|------|

| **処理** | yt-dlp の `--flat-playlist` で公開配信アーカイブ一覧を取得し、処理済み状態と突き合わせる |
| **出力** | 一覧表示（タイトル・尺・投稿日・処理済みバッジ）、選択して一括処理へ投入 |

### FR-13: ハイライトまとめ動画の生成

### FR-14: 縦型ショート動画の生成

| 項目 | 内容 |
|------|------|
| **入力** | 区間（開始・終了）、レイアウト種別、字幕焼き込みの有無 |
| **処理** | 1080x1920 に変換（ぼかし背景合成 または 中央クロップ）。任意で既存 VTT 字幕を焼き込む |
| **出力** | 縦型 mp4（`shorts/output/`）とコマンドログ |
| **スコープ** | **既存字幕の描画のみ。** 新規テロップの生成・配置は含まない |

### FR-15: ストレージ管理

| 項目 | 内容 |
|------|------|
| **入力** | なし（`data/` を走査） |
| **処理** | 容量の集計、元動画キャッシュの選択削除・一括削除 |
| **出力** | 容量サマリー表示、削除結果 |
| **スコープ** | 削除対象は元動画（`clips/source/`）と中間ファイルのみ。成果物は削除しない |

## 8. 追加する受け入れ基準（V0 で requirements.md に転記する）

- [ ] 選択した複数本を一括処理に投入できる
- [ ] 限定公開・メンバー限定動画が一覧に出ない

### AC-15: ストレージ管理

- [ ] 動画ごとの元動画キャッシュ容量が表示される
- [ ] 元動画を削除しても、チャプター・全文・候補・切り出し済み mp4 が残る
- [ ] N 日以上前の元動画を一括削除でき、実行前に対象件数と容量が提示される

- [ ] ぼかし背景レイアウトで、元の横動画が切れずに中央に配置される

- [ ] 字幕のタイミングが映像とズレない
- [ ] 10 秒未満・180 秒超の区間は日本語エラーで拒否される

## 9. 推奨実装順序（依存関係）

```
V0 要件改訂
 └─ V1 機能分離・コピー         ★最初のユーザー価値（半日〜1日で効く）
     ├─ V2 非同期・ステータスバー  ★V5/V6 の前提
     │   ├─ V3 チャンネル取得      ★体感改善が最大
     │   └─ V4 ストレージ管理      ★V5/V6 の前提
     │       ├─ V5 ハイライト
     │       └─ V6 ショート
     └───────── V7 受け入れ
```

**順序の根拠:**

| 判断 | 理由 |
|------|------|
| V1 を最優先 | 半日〜1日で、毎日の「やり直し」コストが劇的に下がる。他の全機能の土台にもなる |
| V2 を V5/V6 より先 | ハイライト・ショートは ffmpeg 再エンコードで数分かかる。同期実行のままでは使い物にならない |
| V3 を V5/V6 より先 | 実装が軽い（1日）割に、URL コピペが丸ごと消えるので体感の改善幅が最大 |
| V4 を V5/V6 より先 | V5/V6 は中間ファイルを大量生成する。容量対策が無いと数十 GB 溜まって詰む |
| V5 を V6 より先 | V5 で作る「区間の複数選択 UI」と「再エンコード付き切り出し」を V6 が再利用できる |

**短縮したい場合:** V3（チャンネル取得）は独立性が高いので、V5/V6 の後に回しても依存関係は壊れない。ただし体感改善が大きいので、優先度は落とさないことを推奨する。

## 12. テスト計画（フェーズ横断）

| 種類 | 対象 | タイミング |
|------|------|------------|
| ユニット | パイプライン分岐、ジョブ状態遷移、チャンネル URL 正規化、容量集計、ハイライトバリデータ、フィルタグラフ生成 | 各フェーズ内 |

- **v1 の既存テストを 1 件も壊さないこと。** 壊れた場合は後方互換の設計ミスとして扱う

## 13. リスクと計画上の対策

| リスク | 計画上の扱い |
|--------|--------------|
| Streamlit のスレッド制約でジョブ機構が破綻する | V2 で「ワーカーから `st.*` を呼ばない」を設計原則として固定。状態はファイル経由のみ |
| ffmpeg の連結で繋ぎ目が壊れる | V5 で再エンコードを必須とする。`-c copy` 連結は採用しない |
| 日本語字幕が豆腐になる | V6 でフォント明示指定 + フォールバック + 起動時警告 |
| 元動画で容量が溢れる | V4 を V5/V6 より前に実施する |
| yt-dlp のチャンネル一覧仕様が変わる | V3 でエラーを日本語化し、`--flat-playlist` 失敗時に手動 URL 入力へ誘導する |
| Codex CLI の応答が不安定 | v1 と同じく softfail + 再生成導線。ハイライト失敗が他成果物に波及しない設計にする |
| v2 の機能追加で UI が複雑になる | タブ構成を「実行 / チャンネル / 処理済み一覧」の 3 つに保つ。ハイライト・ショートは結果表示の下に折りたたむ |
