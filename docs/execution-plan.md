## 1. 目的

本計画は、要件定義（FR / NFR / AC）と技術スタックに沿って、**ローカル Web UI 中心の MVP** を段階的に実装するための実行手順である。

ゴールは次の一連操作が非エンジニアでも成立することである。

1. `start.command` をダブルクリックしてアプリを起動する
2. YouTube アーカイブ URL を貼り付けて「実行」を押す
3. タイムラインが表示され、「コピー」で概要欄に貼れる
4. 切り抜き候補から区間を選び、「切り出し」で動画ファイルを得る

---

## 2. 前提・制約（計画に固定する）

| 項目 | 内容 |
|------|------|
| 主要 UI | Streamlit（localhost のみ） |
| 処理層 | `services/` 共通。CLI は上級者向け補助 |
| コスト | 従量課金 API 禁止。Codex CLI（主）/ Cursor（補助） |
| 取得 | yt-dlp 最新版必須。字幕は `ja-orig,ja` |
| 切り出し | ffmpeg。自動編集はしない |
| 出力ルール | `0:00 タイトル`、半角 `<>` 禁止、先頭 `0:00`、3件以上・各10秒以上 |
| 対象動画 | 公開アーカイブのみ（限定公開・メンバー限定は対象外） |

---

## 3. 実装方針

### 3.1 縦一本を先に通す

最初に「URL 1 本 → 字幕 → 整形 → チャプター → UI 表示・コピー」を通す。  
切り抜き・バッチ・CLI は、その後に同じ services へ載せる。

### 3.2 レイヤ分離

```
UI (Streamlit) / CLI (typer)
        ↓
services (pipeline, ytdlp, vtt, compressor, ai, ffmpeg)
        ↓
data/{video_id}/ ...
```

UI にビジネスロジックを書かない。進捗は pipeline からコールバックで UI に返す。

### 3.3 AI 連携

1. プロンプトテンプレートを `prompts/` に分離する
2. v1 主方式は Codex CLI サブプロセス呼び出し
3. 失敗時は「プロンプトファイルを開いて Cursor で生成」できるフォールバックを残す
4. 保存前にチャプター形式バリデーションを必ず通す

### 3.4 Git コミット方針（必須）

| タイミング | ルール |
|------------|--------|
| **フェーズ完了時** | **必ずコミットする。** メッセージにフェーズ ID（例: `P0`, `P3`）と完了内容を含める |
| **大きな実装タスク完了時** | **そのタスク単位でもコミットする。** 例: `ytdlp.py` 実装完了、Streamlit 縦一本 UI 完了、ffmpeg 切り出し完了など、単独でレビュー・巻き戻しできる塊 |
| **小さな修正のみ** | 同一フェーズ内でまとめてよいが、フェーズ境界では必ず切る |
| **進捗チェック更新** | タスク完了チェック（`- [x]`）とフェーズ状態の更新を、対応する実装コミットに含める（または直後の docs コミットで反映） |

コミットメッセージ例:

```text
feat(P1): yt-dlp による字幕取得と meta 保存を追加

fix(P2): チャプターバリデーションで半角<>を拒否

docs(P3): 実行計画の進捗チェックを更新
```

## 11. 本計画のスコープ外（実装しない）

要件定義どおり、以下は本実行計画に含めない。

- ジャンプカット / テロップ / BGM 等の自動編集

- YouTube 概要欄への自動投稿
- YouTube Data API
- Web UI の外部公開
- 限定公開・メンバー限定動画対応
