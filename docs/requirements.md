# yt-live-kit 要件定義書

**バージョン:** v1（MVP）  
**最終更新:** 2026-07-30  
**対象:** ローカル Web UI ツール「yt-live-kit」

---

## 1. 概要・背景・課題

### 1.1 概要

yt-live-kit は、YouTube ライブ配信アーカイブ向けの **ローカル Web UI ツール** である。ブラウザ上で操作し、入力は公開アーカイブの URL のみとする。日本語自動字幕の取得・整形、YouTube 概要欄用タイムライン（チャプター）案の生成、切り抜き候補の提案と ffmpeg による切り出しまでを、ほぼ自動・高精度で支援する。処理パイプラインは yt-dlp 字幕取得 → VTT 整形 → チャプター生成 → 切り抜き候補 → ffmpeg 切り出しの順で実行される。

### 1.2 背景

- **チャンネル:** AI整体師
- **配信内容:** 約 9 割が AI・AI 経営の話題、たまに整体の話
- **アーカイブ規模:** 100 本超。ほとんどが約 2 時間（短いものもある）
- **運用方針:** 従量課金 API は使わず、yt-dlp / ffmpeg / ローカル Whisper 等の無料ツールと、既存サブスクリプション内の AI（Cursor / Codex CLI 等）のみで運用する

### 1.3 解決したい課題

| 優先度 | 課題 | 現状の負担 |
|--------|------|------------|
| **最優先** | 各アーカイブに YouTube 概要欄用タイムライン（チャプター）を付ける | 2 時間配信ごとに手作業で章立て・時刻入力が必要 |
| **次点** | 切り抜き動画の素早い対応 | 候補区間の探索と ffmpeg 切り出しを手作業で実施 |
| **付随** | 文字起こし全文テキストの保存 | アーカイブごとに参照可能なテキスト資産が欲しい |

### 1.4 検証済みの前提（2026-07-30 実機検証）

以下は v1 設計の前提として扱う。

- 最新の yt-dlp（2026.07.04）で、対象チャンネルのライブアーカイブから日本語自動字幕（`ja-orig` / `ja`、VTT 形式）が取得できる。手動字幕はなし。音声・動画フォーマットも取得可能。
- 古い yt-dlp（2025.02.19）では取得に失敗した。**yt-dlp を最新に保つ運用が必要。**
- 自動字幕の品質: 話題の切れ目判定には十分。ただし固有名詞の誤変換あり（例: 「Codex」→「コードレッ飛ボスり」）。視聴者への挨拶（「〇〇さんこんばんは」等）が大量に混ざる。
- YouTube の VTT 自動字幕は行の重複（プログレッシブ表示）を含むため、**重複除去・整形処理が必要。**
- 検証例: 1 時間 24 分の配信から約 950 キューを整形し、20 秒単位のバケットに圧縮して約 41KB のテキストにできた。これを AI に読ませてチャプター案を生成する流れが成立した。

## 2. 対象ユーザーと利用シーン

### 2.1 対象ユーザー

- YouTube でライブ配信を行うクリエイター（本プロジェクトでは AI整体師チャンネルを主対象とする）
- **非エンジニア** で、ターミナル操作に不慣れ。ブラウザ上のボタン操作で完結させたい
- Cursor / Codex 等の既存 AI サブスクリプションを利用している（初期セットアップは Cursor 等の AI エージェントの支援を受けて行う想定）

### 2.2 起動・操作の前提

- アプリの起動は **ダブルクリック**（macOS の `.command` ファイル）または **1 コマンド**（`uv run streamlit run ...`）で行えること
- 日常の操作はすべてブラウザ上で完結する（URL 貼り付け → ボタン押下 → 結果確認・コピー）

### 2.3 利用シーン

| シーン | 説明 |
|--------|------|
| **単本処理** | URL 入力欄にアーカイブ URL を貼り付け、「実行」ボタンで字幕取得 → チャプター案生成まで一括実行。タイムラインをコピーして概要欄に貼り付け |
| **バッチ処理** | テキストエリアに複数 URL を貼り付け、順次処理（失敗時は再開・スキップ） |
| **切り抜き作成** | 画面上の切り抜き候補一覧から区間を選び、「切り出し」ボタンで ffmpeg 実行 |
| **過去成果物の参照** | 処理済み動画一覧から、以前のタイムライン・文字起こし・候補をあとから開く |
| **資産保存** | 動画 ID ごとに字幕・整形テキスト・チャプター・候補リストをローカルに蓄積 |

## 3. 機能要件

### FR-01: 字幕・メタデータ取得

| 項目 | 内容 |
|------|------|
| **入力** | YouTube 公開アーカイブ URL（1 本）、Web UI のテキストエリア、または URL 一覧ファイル（1 行 1 URL） |
| **処理** | yt-dlp により動画メタデータ（タイトル、公開日、動画 ID 等）と日本語自動字幕（VTT）を取得する |
| **出力** | 動画 ID ごとのディレクトリにメタデータ（JSON）と字幕原本（VTT）を保存 |
| **成功条件** | `ja-orig` または `ja` の VTT が取得・保存されること |
| **失敗時** | エラーを記録し、バッチ処理時は当該 URL をスキップして次へ進む |

### FR-02: VTT 整形

| 項目 | 内容 |
|------|------|
| **入力** | FR-01 で保存した VTT ファイル |
| **処理** | プログレッシブ表示による行の重複を除去し、タイムスタンプ付きテキストに整形する。加えて AI 入力用に 20 秒単位バケット等で圧縮版テキストを生成する |
| **出力** | 全文版テキスト、圧縮版テキスト（いずれもタイムスタンプ付き） |
| **成功条件** | 重複除去済みの全文版と、AI に渡せるサイズの圧縮版が生成されること |

### FR-03: チャプター案生成

| 項目 | 内容 |
|------|------|
| **入力** | FR-02 の圧縮版（または全文版）テキスト、プロンプトテンプレート |
| **処理** | 整形テキストを Cursor / Codex（既存サブスク）に渡し、YouTube 概要欄用タイムラインを生成する。視聴者挨拶・雑談ノイズを除外し、話題の切れ目基準で章立てする。字幕の固有名詞誤変換は AI 側で補正する |
| **出力** | チャプター案（Markdown / テキスト）。出力形式ルールは「5. 出力仕様」を参照 |
| **成功条件** | 形式ルールを満たすチャプター案が 3 件以上生成されること |

### FR-04: 切り抜き候補の提案

| 項目 | 内容 |
|------|------|
| **入力** | FR-02 の整形テキスト、チャプター案（任意） |
| **処理** | 10〜15 分程度のまとまった区間を想定し、複数の切り抜き候補（開始・終了時刻、タイトル、選定理由）を生成する |
| **出力** | 切り抜き候補リスト（JSON または Markdown） |
| **成功条件** | 2 件以上の候補区間が時刻付きで出力されること |

### FR-05: 切り抜き動画の切り出し

| 項目 | 内容 |
|------|------|
| **入力** | YouTube URL、開始時刻、終了時刻（人が FR-04 の候補から選択した区間） |
| **処理** | yt-dlp で動画をダウンロードし、ffmpeg で指定区間を 1 本切り出す |
| **出力** | 切り出し済み動画ファイル、実行した ffmpeg コマンドの記録 |
| **成功条件** | 指定区間の動画ファイルが生成されること |
| **スコープ** | **切り出しのみ。** ジャンプカット、テロップ、BGM 等の自動編集は含まない |

### FR-06: 成果物のファイル保存

| 項目 | 内容 |
|------|------|
| **入力** | 各 FR の処理結果 |
| **処理** | 動画 ID ごとにディレクトリを作成し、関連ファイルを一括保存する |
| **出力** | 「5.2 出力ディレクトリ構成」を参照 |
| **成功条件** | 1 回の処理完了後、当該動画 ID ディレクトリに必須ファイルが揃っていること |

### FR-07: 一括実行（run）

| 項目 | 内容 |
|------|------|
| **入力** | URL または URL 一覧（Web UI のテキストエリア、または上級者向け CLI の一覧ファイル） |
| **処理** | FR-01 → FR-02 → FR-03 → FR-04 を順に実行する（FR-05 は人の選択後に個別実行） |
| **出力** | 各動画 ID ディレクトリ一式 |
| **成功条件** | 処理済み URL の成果物が保存され、失敗 URL はログに記録されること |

### FR-08: Web UI（主要インターフェース）

| 項目 | 内容 |
|------|------|
| **入力** | ユーザーのブラウザ操作（URL 貼り付け、ボタン押下、候補選択） |
| **処理** | FR-01〜FR-07 と同一のパイプラインを services 層経由で呼び出し、結果を画面に表示する |
| **成功条件** | 以下の UI 機能がすべて利用可能であること |

**FR-08 の詳細要件:**

| # | 機能 | 内容 |
|---|------|------|
| 1 | **単本実行** | URL 入力欄に貼り付けて「実行」ボタンを押すだけで、fetch → transcript → chapters → clips suggest が走る |
| 2 | **進捗表示** | 処理中は現在の工程（字幕取得中、整形中、チャプター生成中 等）を画面に表示する |
| 3 | **タイムライン表示・コピー** | 完了後、チャプター案（タイムライン）を画面表示し、「コピー」ボタンでクリップボードへコピーできる |
| 4 | **文字起こし全文** | 整形済み全文テキストの表示とダウンロードができる |
| 5 | **切り抜き候補・切り出し** | 候補を一覧表示し、候補を選んで「切り出し」ボタンで ffmpeg を実行。完成ファイルの保存先を画面に表示する |
| 6 | **処理済み一覧** | 過去に処理した動画の一覧を表示し、成果物をあとから開ける |
| 7 | **一括処理** | テキストエリアに複数 URL を貼り付けて順次処理できる（FR-07 の UI 版） |

**補足:** CLI（サブコマンド）は v1 でも提供するが、**内部実装・上級者向けの補助** と位置づける。Web UI と CLI は同じ services 層を呼び出す。

## 4. 非機能要件

### NFR-01: コスト制約

- **従量課金 API は使用しない。** OpenAI API、Google Cloud Speech-to-Text、有料文字起こしサービス等は v1 スコープ外とする。
- AI 連携は Cursor / Codex CLI 等、既存サブスクリプション内のツールのみとする。
- 外部ツールは yt-dlp、ffmpeg、ローカル Whisper（v1.5 フォールバック）等の無料・ローカル実行可能なものに限定する。

### NFR-02: バッチ処理

- 100 本超のアーカイブを URL 一覧から順次処理できること。
- 処理状態（成功 / 失敗 / スキップ）をログまたはステータスファイルで記録すること。

### NFR-03: 障害耐性・再開

- 途中で失敗した場合、処理済み URL はスキップし、未処理 URL から再開できること。
- 個別 URL の失敗がバッチ全体を停止させないこと（設定で停止も可能とする）。

### NFR-04: yt-dlp 更新運用

- yt-dlp は定期的に最新版へ更新する運用を前提とする（古いバージョンでは字幕取得に失敗する実績あり）。
- バージョン情報をログまたはメタデータに記録し、問題発生時の切り分けに使えること。

### NFR-05: レート制限対策

- YouTube 側のレート制限を考慮し、連続リクエスト間にスリープを挟めること（間隔は設定可能とする）。

### NFR-06: 対象外コンテンツ

- **限定公開・メンバー限定動画は v1 の対象外**とする（公開アーカイブのみ）。
- 手動字幕のみで自動字幕がない動画は v1 ではエラーとし、v1.5 の Whisper フォールバックで対応を検討する。

### NFR-07: 実行環境

- macOS（開発環境）を主とし、Python 3.11+、ffmpeg（ローカルインストール済み: 8.0.1）、yt-dlp が利用可能であること。

### NFR-08: データ永続化

- データベースは使用しない。JSON + Markdown / テキストのファイルベース保存とする。

### NFR-09: 非エンジニア向け運用性

- **非エンジニアが一人で日常運用できる** こと（初期セットアップを除く）
- 起動手順は **1 ステップ**（ダブルクリックまたは 1 コマンド）。README に非エンジニア向けの起動手順を記載する
- エラー発生時は **日本語** で原因と対処方法を画面に表示する（技術的なスタックトレースのみの表示は避ける）

### NFR-10: ローカル実行

- Web UI は **ローカルホスト上でのみ** 動作する（`localhost`）。外部公開・インターネット経由のアクセスは v1 スコープ外
- 処理データ（字幕、動画、成果物）はすべてローカルディスクに保存する

## 5. 出力仕様

### 5.1 YouTube 概要欄用タイムライン形式ルール

以下は **必須ルール** である。FR-03 の出力および最終的な概要欄貼り付け時に遵守する。

| ルール | 内容 |
|--------|------|
| **形式** | `0:00 タイトル`（時刻 + 半角スペース + タイトル） |
| **半角山カッコ禁止** | 半角の `<` `>` は使用禁止（YouTube 概要欄で使えない／崩れるため）。タイトル内にも半角 `<>` を入れない |
| **代替表記** | 必要なら全角 `〈〉` や別表現に置換する |
| **先頭チャプター** | 最初のチャプターは **必ず `0:00` から始める** |
| **件数・長さ** | チャプターは **3 つ以上**、各チャプターは **10 秒以上**（YouTube の仕様） |
| **目安** | 2 時間配信では **15〜25 個程度** を目安とする |
| **内容方針** | 視聴者挨拶・雑談ノイズを除外し、**話題の切れ目** 基準で章立てする |
| **固有名詞** | 字幕の誤変換（固有名詞等）は AI 側で補正する |

**出力例:**

```
0:00 配信開始・本日のテーマ紹介
3:42 Cursor Agent の使い方デモ
12:15 AI経営における現場の違和感
25:30 質疑応答・Codex CLI の話
```

### 5.2 出力ディレクトリ構成（例）

動画 ID を `{video_id}` とする。

```
data/
└── {video_id}/
    ├── meta.json              # タイトル、URL、公開日、yt-dlp バージョン等
    ├── subtitles/
    │   └── ja.vtt             # 字幕原本（VTT）
    ├── transcript/
    │   ├── full.txt           # 整形済み全文（タイムスタンプ付き）
    │   └── compressed.txt     # AI 入力用圧縮版
    ├── chapters/
    │   └── chapters.md        # チャプター案（概要欄用タイムライン）
    └── clips/
        ├── candidates.json    # 切り抜き候補リスト
        └── output/            # ffmpeg 切り出し結果（FR-05 実行時）
            └── clip_001.mp4
```

### 5.3 切り抜き候補フォーマット（例）

```json
{
  "candidates": [
    {
      "id": "clip_001",
      "title": "Cursor Agent デモまとめ",
      "start": "00:03:42",
      "end": "00:16:30",
      "duration_sec": 768,
      "reason": "AI ツール実演が一続きで説明されている区間"
    }
  ]
}
```

## 6. スコープ外

### 6.1 v1（MVP）に含まないもの

| 項目 | 理由 |
|------|------|
| 自動編集（ジャンプカット、テロップ、BGM、まとめ編集） | MVP は候補提案と ffmpeg 切り出しまで |
| 全本一括の Whisper 再文字起こし | コスト・時間の観点から v1 では字幕取得のみ |
| YouTube 概要欄への自動投稿 | 人手でコピー＆貼り付け（UI のコピーボタンで支援） |
| YouTube Data API の利用 | 従量課金・認証の複雑さを避ける |
| 限定公開・メンバー限定動画 | 公開アーカイブのみ対象 |
| Web UI の外部公開（クラウドホスティング等） | ローカル実行のみ。セキュリティ・運用の簡素化 |

### 6.2 v1.5 展望

- **Whisper フォールバック:** 字幕が無い、または品質が著しく低い回のみ faster-whisper でローカル再文字起こし
- **複数候補の一括切り出し:** FR-04 で生成した複数候補を一括で ffmpeg 切り出し

### 6.3 v2 展望

- 切り抜き編集の自動化（ジャンプカット、テロップ等）— スコープ・工数が大きいため v2 以降
- チャンネル全体の定期クロール（新規アーカイブの自動検知）
- リモートアクセスや複数端末からの利用（現状は localhost のみ）

## 7. 受け入れ基準

v1 MVP として以下をすべて満たすこと。

### AC-01: 字幕取得

- [ ] 公開アーカイブ URL 1 本から、日本語自動字幕 VTT が取得・保存される
- [ ] 取得に使用した yt-dlp のバージョンが記録される

### AC-02: VTT 整形

- [ ] プログレッシブ重複が除去された全文版テキストが生成される
- [ ] 20 秒単位バケット等で圧縮された AI 入力用テキストが生成される
- [ ] 1 時間超の配信で、圧縮版が AI のコンテキスト制限内に収まる

### AC-03: チャプター生成

- [ ] 圧縮版テキストから、形式ルール（5.1）を満たすチャプター案が生成される
- [ ] 先頭が `0:00`、3 件以上、各 10 秒以上である
- [ ] 視聴者挨拶が章タイトルに含まれない（話題ベースの章立て）
- [ ] 半角 `<>` が出力に含まれない

### AC-04: 切り抜き候補

- [ ] 10〜15 分程度の候補区間が 2 件以上提案される
- [ ] 各候補に開始・終了時刻とタイトルが含まれる

### AC-05: 切り抜き切り出し

- [ ] 人が選んだ 1 区間について、ffmpeg で動画が切り出される
- [ ] 実行コマンドが記録される

### AC-06: バッチ処理

- [ ] Web UI のテキストエリア、または URL 一覧ファイルから複数本を順次処理できる
- [ ] 1 本失敗しても残りが処理される
- [ ] 再実行時に処理済み URL をスキップできる

### AC-07: コスト

- [ ] 従量課金 API を一切呼び出さない（コード・設定の両面で確認）

### AC-08: 成果物

- [ ] 動画 ID ごとのディレクトリに、5.2 で定義した必須ファイルが保存される

### AC-09: Web UI（主要フロー）

- [ ] README の手順どおりに、非エンジニアがアプリを起動できる（ダブルクリックまたは 1 コマンド）
- [ ] URL を入力欄に貼り付け →「実行」ボタン → タイムラインが画面表示 →「コピー」ボタンでクリップボードにコピー、が一連で成功する
- [ ] 処理中に現在の工程が表示される
- [ ] 文字起こし全文の表示・ダウンロードができる
- [ ] 切り抜き候補一覧から候補を選び、「切り出し」で ffmpeg が実行され、保存先が表示される
- [ ] 処理済み動画一覧から過去の成果物を開ける
- [ ] 複数 URL の一括処理がテキストエリアから実行できる
- [ ] エラー時に日本語で原因と対処が表示される

### AC-10: ローカル実行

- [ ] Web UI が localhost のみで動作し、外部公開されていない

| チャプター / タイムライン | YouTube 概要欄に記載する `0:00 タイトル` 形式の章立て |
| 圧縮版テキスト | AI 入力用に 20 秒単位バケット等で要約・圧縮した字幕テキスト |
| 候補区間 | 切り抜き動画として提案される開始・終了時刻の組 |
| VTT | WebVTT 形式の字幕ファイル。YouTube 自動字幕の取得形式 |
| Web UI | ブラウザ上で操作するローカルインターフェース（Streamlit）。v1 の主要操作手段 |
| CLI | コマンドラインインターフェース。v1 では内部実装・上級者向け補助として提供 |
